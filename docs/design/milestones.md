# 里程碑与验收

> 原则：每一步都是「可演示的稳定切片」，验收必须有真机证据。时长按 1 人全职估算，可并行压缩。

## M0 · 架构 Spike（1–2 周）

**目标**：确定嵌入路线（ADR-0003）与工作区方案，排除最致命的技术风险。

| 任务 | 产出 |
|---|---|
| 验证官方 Remote 内核是否可被第三方插件使用（`@deepseek-ai/dsh-api-remotes` 等） | 结论 + 最小 demo/失败原因 |
| 槽位最小原型：`sidebar.panellist` + `main`/`shell.overlay` 挂向导与面板 | 可跑的原型 |
| iframe 原型：本地回环代理 → 远端 dsh 页面，cookie/token/父窗口校验 | 结论 + 风险 |
| 工作区注册实验：锚点目录 vs 元数据工作区 | 结论 |
| 远端 companion 最小通讯（健康检查 + 版本上报） | 协议草案 |

**出口**：ADR-0003 定稿；`docs/design/architecture.md` 更新；风险表更新。

## M1 · WSL 流畅闭环（2–4 周）

**目标**：WSL 后端从零到「可用」，达到验收 A1–A8（SSH 可后补）。

| 任务 | 验收 |
|---|---|
| Backend 抽象 + WSL 实现（探测/引导/启动/无隧道 localhost 转发） | 真机连上 WSL 并启动远端 dsh |
| 四步向导（方式/配置/连接/选目录）+ 进度/取消/错误分阶段 | 用户能独立完成一次连接 |
| 工作区与会话投影（侧栏出现远端工作区、可新建会话） | 会话首个命令在远端执行（`pwd`/`uname` 断言） |
| 凭据代理（占位令牌 → 本地替换） | 远端环境无真实 key；推理可用 |
| 断线与重连、进程回收、退出策略 | 杀隧道/重启远端后可恢复；无孤儿进程 |
| 环境策略 v1（至少 isolated；评估 reuse） | 行为可预期 |

**出口**：WSL 真机演示：本地侧栏打开远端工作区 → 新建会话 → 远端执行 → 断线重连 → 退出回收。

## M2 · SSH 后端（2–3 周）

| 任务 | 验收 |
|---|---|
| SSH config 解析与校验（`~` 展开、`.pub` 误配、跳板链） | 用本机真实 config 全量通过（含错误配置的可操作提示） |
| 认证：私钥 / agent / 密码（含口令） | 三种都能连 |
| known_hosts TOFU / 指纹变更拦截 | 首次接受、变更拒绝 |
| SSH 隧道 + per-host 回环代理 | 与 WSL 共用上层，无重复实现 |
| 引导器：远端 Node/dsh 安装（镜像测速、缓存、断点） | 首次 ≤ 可接受时间且可取消；二次秒级 |

**出口**：同一套 UI 与语义下，SSH 达到 A1–A8。

## M3 · 「丝滑」打磨（2–3 周）

| 任务 | 验收 |
|---|---|
| 环境共享：`reuse` 远端 `~/.dsh`（版本校验 + 用户确认） | 远端已有插件/技能原生可用（A3 真机证据） |
| 可选同步：插件/技能/配置（逐条勾选、不覆盖、凭据不同步） | 同步后远端可用；失败项可诊断 |
| 统一会话列表/搜索/归档（远端会话与本地同列） | 单一列表可操作远端会话 |
| 账号/用量端点的代理或明确降级 | 不再出现 200+非 JSON |
| 多工作区/多 host 同时在线、引用计数 | 不互相踩进程/端口 |
| 诊断中心（doctor、日志导出、版本矩阵） | 用户可自助定位常见失败 |

## M4 · 发布（1–2 周）

| 任务 | 验收 |
|---|---|
| 兼容矩阵（0.2.0 / 0.2.1 线）+ CI | 两端均通过 |
| 安装器/市场发布/文档/中英文 | 新用户按文档可独立完成 |
| 安全评审（凭据、隧道、iframe、远端权限） | 无高危项 |
| 卸载干净（进程、隧道、缓存、远端资源策略） | 卸载后无残留（远端用户数据可保留） |

## 全程质量门

- 每步都跑：单元测试 + WSL 真机 + SSH 真机（至少一台）；
- 关键路径「远端执行」必须有断言（`uname -a` / `pwd` / 远端文件写入后读回）；
- 失败路径必须有测试：断线、版本不匹配、目录不可写、远端无 Node、端口占用；
- 文档同步（README/design/ADR）；未验证项明确标注。
