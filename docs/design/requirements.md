# 需求

> 一句话：**在 Windows 上打开 DSH，选择一台 WSL 发行版或 SSH 主机，像打开本地项目一样打开远端目录；agent、插件、会话、文件全部在远端，GUI 只有一个。**
> 状态：v0.1（2026-10-19，调研完成后的需求基线）

## 1. 背景与用户原话

- 用户在使用「WSL 工作区」类插件（A 型）后发现：**WSL 里为 dsh 装的插件/工具用不了**。
- 实测 `dsh-remote-explorer`（B 型）后判断：**能做到宿主在远端，但不够丝滑**（独立页面、首次连接重、环境不共享、账号面板报错、两套历史）。
- 结论：需要一个自研的 B 型插件，且必须把「集成体验」做到接近 VS Code Remote / ZCode / Zed。

## 2. 目标用户

| 用户 | 场景 |
|---|---|
| Windows 上做 Linux 开发的个人开发者 | 项目依赖、工具链、插件都在 WSL 里；想在 DSH Desktop 里直接开发 |
| 有多台远端机器的开发者 | 代码/依赖在服务器上，本地只做界面；需要与本地工作区混用 |
| 团队/受管环境 | 凭据不能落到远端；需要可审计的连接、版本可控的远端运行时 |

## 3. 用户故事

1. 作为开发者，我在侧栏点「添加远程工作区」，选 WSL 发行版或 SSH 主机，填/选配置，看到连接进度，最后选一个远端目录 → 该目录以一个**远端工作区**出现在侧栏，和本地项目并列。
2. 我打开这个工作区新建会话，agent 的 `bash`、文件读写、搜索、终端**全部在远端执行**；我能在会话里看到远端路径。
3. 我在远端原本就有一套 DSH 环境（`~/.dsh`、插件、技能、settings），我可以选择**复用它**，而不是被迫用一套隔离的空环境；也可以选择隔离或显式同步。
4. 首次连接时我能看到分阶段进度（探测/下载/安装/启动/隧道），可以取消；第二次连接**秒级**进入。
5. 连接断了（网络/休眠/远端重启），侧栏工作区显示状态，我点重连即可恢复；远端进程不会变成孤儿。
6. 我的 API key / 账号 token **永远不出本机**；远端只能看到占位令牌。
7. 远端不可用、版本不匹配、目录不可写、没有 Node 时，我得到**明确的分阶段错误**和可复制的日志，而不是静默回落到本地执行。

## 4. 验收标准（产品基线）

任一里程碑交付前，**该里程碑声明覆盖的验收项**都要有真机证据。后端维度不在此一次性锁死，按 A9 的分阶段承诺执行：M1 出口只要求 A1–A8 的 **WSL 轮**；**SSH 轮必须在 M2 交付前补齐**，M1 不得宣称 A9 通过。（R1-20：原句要求「每条都要 WSL + SSH 各至少一轮」，与 A9 的「允许 SSH 在 M2 补齐」互斥，等于开了一条「SSH 完全未验证也能签 M1」的通道。）

| # | 验收项 | 判据 |
|---|---|---|
| A1 | 原生入口 | 远端工作区出现在**本地原生 UI**（「远端工作台」面板，`sidebar.panellist` + `main`）里，**与本地工作区在同一视图内混排**、可比较可切换，带后端类型与主机标识；不新开网页/浮动窗口。判据与槽位依据见 `ui-design.md` §2–§3、`ADR-0005` |
| A2 | 宿主在远端 | 远端存在 `dsh` 宿主进程；会话的模型请求由远端进程发起；关掉本地 GUI 不影响远端会话数据 |
| A3 | 远端插件可用 | 远端已装/同步的插件（如 hindsight）在远端会话里**真的注册了工具/钩子**（不是只看到文件） |
| A4 | 环境可选 | 「隔离 / 复用远端 `~/.dsh` / 显式同步」三档至少两档可用，且状态可见 |
| A5 | 首连体验 | 有分阶段进度（探测/下载/校验/解压/安装/启动/隧道/同步屏障）与取消；已引导目标二次连接 ≤ 5s（**测量方法见 §7.1**）。**取消能力分级（2026-11-13，R1 五轮后由所有者收口）**：① **保证**——`probe` / `bootstrap` / `launch` / `tunnel` 四段的取消必须落到宿主（`/attach` 终态 `remote/cancelled`；真机 `G-A5-2b` 取证）；② **尽力而为**——`attach` RPC 段与 `#connect` 内部的取消（可能落在握手/建连之后；回滚按「本次新建 vs 复用连接」判定）；③ **不承诺**——取消后远端进程立刻退出（回收归退出/看门狗，见 `architecture.md` §8.5）。剩余已知缺陷（D7）与未验证子句见签署归档 §3，转 M3 输入 |
| A6 | 凭据边界 | 远端进程环境/磁盘中只有占位令牌；真实 key 仅在本机；抓包/日志可证。**取证口径**：本机代理侧必须有该远端 host 的**实际入站请求记录**（含占位令牌被替换的日志行），仅「配置文件里写的是代理端点」不算通过——这是 R1-1 的直接教训 |
| A7 | 断线恢复 | 网络中断/远端重启后，工作区状态可见、可一键重连，远端进程可回收（不留孤儿） |
| A8 | 失败可诊断 | 每阶段失败有结构化错误码 + 可复制日志 + 重试入口；不出现「远端不可用却本地执行」 |
| A9 | 后端矩阵 | WSL2 与 SSH 两条链路都达到 A1–A8（按 WSL → SSH 顺序交付）。**A9 是 M2 的验收项，不是 M1 的**：M1 只签 A1–A8 的 WSL 轮，SSH 轮欠账记在 M2，M2 未补齐则 M2 不得出口 |
| A11 | Docker 接口位 | 后端枚举含 `docker`，`create-backend` 对其显式抛「未实现」，UI 显示为不可选并标注计划里程碑；接口形状与 WSL/SSH 同构（probe / installOrUpdate / ensureDaemon / openChannel / exec），使 M5 接入不改上层契约 |
| A10 | 版本兼容 | 声明支持的 DSH 版本矩阵；升级宿主后跑兼容检查；不兼容时**拒绝连接**并说明「当前版本 / 最低版本 / 应升级哪一端」；兼容但版本不同时**只给非阻塞提示**，不阻断连接 |

## 5. 非目标（v1 明确不做）

1. ~~**Docker** 后端~~ → **改为 M5 交付**（2026-10-26 用户改口：WSL 先做、SSH 次之、**Docker 最后做**）。v1 仍不交付 Docker 可用链路，但接口位与 UI 占位必须在 M1 前留好，见 A11 与 `ADR-0005` §决策 4。
2. 完整 IDE 能力（Monaco/LSP/调试器）。
3. 多人协作 / 共享会话。
4. 纯 headless 部署（无本地 GUI）。
5. 不做 A 型（远端执行）插件；如将来需要，作为可选「world 后端」，不作为主形态。
6. 不做任意云厂商/Codespaces 的专用适配（SSH 能到就行）。

## 6. 约束

- 目标宿主：DSH Desktop 0.2.x（至少 0.2.0-rc.2 / 0.2.1-rc.2 两线；当前验证基线为 **0.2.2-rc.4**（2026-11-18：本机宿主 `@deepseek-ai/dsh-app-boot 0.2.2-rc.4` 上跑通 WSL 接入 7/7 与 SSH 接入 11/11，见 §6.1；此前基线 0.2.1-rc.5 的 T5 跨机取证见 `spikes/m1/cross-machine-t5/README.md`），dsh web profile 兼容。兼容声明用 **`engines.dsh`** 或 **`@deepseek-ai/dsh-*` 的 `peerDependencies`**（`packages/boot/app-boot/src/plugin-compatibility.ts:55-74` 是唯一读取方；`dsh.compatibility.dshReleases` 在宿主侧零读取方，已废弃），判定规则见 `architecture.md` §5 与 `ADR-0004`。
- Windows 本机 + WSL2；SSH 目标为 POSIX（Linux/macOS）。
- 远端需要 Node + dsh（由我们安装或复用），版本对齐规则由我们定义。
- 不修改 DSH 内核代码；只用已文档化的扩展点；内核缺口用「兼容层 + 明确降级」处理。
- 凭据安全：不把 `.credentials.yaml` 复制到远端。

### 6.1 宿主版本实测记录（0.2.2-rc.4，2026-11-18）

| 项 | 结果 |
|---|---|
| `pnpm check:boot`（补丁行 id / `dsh` 三件套 / 旧名残留） | OK |
| L4 真浏览器（14 场景 + 键盘 10/10） | 通过 |
| WSL 真机接入（`ubuntu_dev`，`spikes/m1/p35-projection`） | **7/7**（launch → workspace/create → UNC stat → session/create 20.8 s → 会话内 `pwd`/`uname` 在 distro 执行 → 投影 online（512 会话）→ dispose 端口释放） |
| SSH 真机接入（`syy_wsl_ubuntu_LAN`，全新引导） | **11/11**（reuse/isolated 两档、DSH_HOME 落点、隔离目录落地、端口释放、两个负控） |

**判定要点**：宿主的兼容判定走 `semver.satisfies(..., { includePrerelease: true })`（`plugin-compatibility.ts:51-53`），所以 `0.2.2-rc.4` 满足 `>=0.2.1-rc.0 <0.3.0`；但**默认 semver 语义下不满足**（预发布 tuple 规则），其他工具报的「不兼容」属警告级，不影响加载。

本轮真机回归顺带修掉两个缺陷：① 刚引导装好 node 后仍用 PATH 上的 `node` 启动（`sh: node: not found`，180 s 超时）；② `sh: 2: node: not found` 未被识别成 `remote/node-missing`，落到泛化的 `startup-failed`。

## 7. 体验基准（「丝滑」的定义，量化）

| 指标 | 目标 |
|---|---|
| 首连（已有远端 dsh/Node）| ≤ 10s 到「可选目录」 |
| 首连（需要安装远端运行时）| 有进度、可取消；安装体积与时间**可见**；同一目标二次连接免安装 |
| 打开工作区 | ≤ 2s 出现于「远端工作台」面板；会话创建后首个命令 ≤ 3s |
| 断线重连 | 自动重试 2s/4s/8s×3 → offline 每 2min 静默探测；状态可见；手动重连 ≤ 5s |
| 错误信息 | 阶段化（探测/安装/启动/隧道/同步屏障/会话）+ 可操作下一步 |
| 断连期行为 | 写与 IO **fail-closed 报错**，不回落本地执行；投影标 `offline` 保留只读 |

### 7.1 测量方法（R1-12 补齐）

上表每个时间指标都必须按下列口径测量，否则不计入验收。

**计时起止点**（与 `architecture.md` §8.1 的状态机对齐，R1-23 修订）

| 指标 | 起点 | 终点 | 明确排除 |
|---|---|---|---|
| 首连（已有远端 dsh） | 用户点击「连接」的 `pointerup` 事件时间戳 | `connected` 状态下「可选目录」列表**首帧渲染完成**（`requestAnimationFrame` 回调内打点） | 远端 dsh 冷启动（`probing`→`provisioning`→`starting` 三段，单列报告） |
| 打开工作区 | 「远端工作台」面板中该工作区条目的点击事件 | 该条目出现在面板列表的可交互态 | 会话创建（另计） |
| 会话创建后首个命令 | 会话创建成功的 `session.created` 事件 | 命令输出首字节回显 | 模型推理时间（属于模型侧，不属本插件） |
| 手动重连 | 用户点击「重连」 | 回到 `connected` | — |

**样本量**：每项 **≥ 5 次连续测量，取 P50 与 P90 两个值**，两个值都要达标才判通过（只用均值会把长尾藏起来）。测量脚本必须把每次的原始时间戳写入 JSON，随验收记录提交。

**冷热缓存**：每项分别测「冷」（进程首次启动、无 OS 文件缓存）与「热」（同进程第 2 次及以后）两组，冷热各出一组 P50/P90。「二次连接 ≤ 5s」只对**热**组生效；冷组作为体验基线记录，不作为门禁。

**基线机**：所有性能类验收必须在 `docs/design/milestones.md` 头部声明的**基线机**上跑，并在记录里写明 CPU / 内存 / 磁盘类型 / 网络（本机回环 or 真实链路）/ WSL 网络模式（NAT or mirrored）。换机器必须重跑并更新基线记录，不允许跨机器比较数字。

**不达标时**：记录实测值 + 瓶颈定位（哪一段耗时最长）+ 是否阻塞本里程碑。**不允许**通过放宽口径、换更快的机器、或只报均值来「达标」。

## 8. 已结案的待确认项

| # | 问题 | 结论 | 依据 |
|---|---|---|---|
| 1 | 环境策略默认值：复用远端 `~/.dsh` vs 隔离+同步 | **默认 `reuse`**；`isolated` 可选；`sync` 需显式勾选 | 用户 2026-10-26 裁决；`architecture.md` §6 |
| 2 | 是否自动同步插件/技能 | **不自动**。`sync` 是显式勾选，缺失项默认勾选、已存在项灰掉不覆盖 | 用户 2026-10-26 裁决；`ADR-0004` |
| 3 | 多远端同时在线 | **v1 单台**，切换即断开上一台；多台留 M3 | 用户 2026-10-26 裁决；`ADR-0005` §决策 5 |
| 4 | 远程工作区被 `remote_control`/手机端访问 | 未定，留后续特性 | — |
| 5 | 同一远端被两个本地 DSH 实例连接 | **不做部署锁，改做端口占用检测**（2026-10-31 裁决，M0 判定完成）。理由：① T6 实测证明两个实例各自 `/connect` 拿**不同** v2 Cookie、`ownsSocket` 是 per-peer，不会互相踢；② 真正冲突只有同一 `DSH_HOME` 上第二个 `dsh web` 触发 `EADDRINUSE`，表现为启动失败而非数据竞争。落地口径：检测到端口被占即返回结构化错误 `remote/port-in-use`，并给三个可选项（复用已有实例 / 另选端口 / 关闭对方进程），**不静默接管、不自动杀进程** | `docs/research/zcode-remote/05-capability-map.md` #31；`spikes/m1/cross-machine-t6/probe.cjs`（T6-4b 双通道实证）；[`plans/2026-10-31-m1-wsl-closed-loop.md`](../project/plans/2026-10-31-m1-wsl-closed-loop.md) §0 B3 |
