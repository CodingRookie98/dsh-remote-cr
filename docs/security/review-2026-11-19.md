# 安全评审（2026-11-19）· 凭据 / 隧道 / iframe / 远端权限

> 结论先行：**未发现高危项**。四条边界（凭据不出本机、只绑回环、无 iframe、远端命令全走转义）都有代码级护栏与用例；
> 下列 3 条低风险与 4 条未验证写明处置，不掩盖。

## 0. 范围与方法

- 范围：`src/local/proxy/**`（凭据代理）、`src/local/backend/{ssh,wsl}/**`（隧道与远端进程）、`src/local/api/**`（本机 HTTP 面）、`src/client/**`（渲染面）。
- 方法：逐文件读码 + 关键不变量 grep + 既有用例核对；**不**对真实第三方远端做攻击性测试（无授权目标）。
- 口径：`docs/design/architecture.md` §7、`docs/design/requirements.md` A6（凭据边界）、铁律 3（凭据不出本机）。

## 1. 凭据边界（A6）—— 强

| 不变量 | 实现 | 证据 |
|---|---|---|
| 代理**只绑回环**，且不是配置项 | `PROXY_BIND_HOST = '127.0.0.1'`；`assertLoopbackBind()` 对任何非回环地址启动即抛 | `src/local/proxy/proxy.ts:24,30-32,141` |
| 远端只拿**占位串** | `mintPlaceholder(ref, salt)` 由 ref 派生（SHA-256 前 96 bit），真值只在本地 `LocalCredentials` | `src/local/proxy/placeholder.ts`、`runtime.ts:46` |
| 远端若带了**非占位串**（「真 key 被同步过去」的事故） | 一律 **403** 并留结构化记录 | `proxy.ts:198-203` |
| 真值来源优先级 | 环境变量 > 凭据文件；两者都不在远端 | `credentials.ts`（含 8 条用例） |
| 代理侧**不打印真值** | `src/local/proxy` 内 `console.*` 命中 **0** | grep 实测 |

**记录面**：每次请求留 `{ at, remote, method, provider, path, status, substitutions[{header, ref}] }`，只有 ref、没有值（`proxy.test.ts:80` 断言）。

## 2. 隧道 —— 中（机制成立，一条历史未验证仍在）

| 面 | 结论 | 证据 |
|---|---|---|
| 正向 `-L` / 反向 `-R` | 同一连接、只连回环；`AllowTcpForwarding no` 时降级 stdio 桥并给 `remote/forward-unavailable` | M2 真机 `spikes/m2/ssh-e2e/forward-denied.ts` 5/5 |
| WSL 通路 | 默认 ③ `wsl.exe --exec` stdio 桥（不经网络）；① `mirrored` 直通仅作优化；② 网关已退役 | `spikes/m1/wsl-closed-loop` |
| 远端「借隧道烧额度」 | 代理只绑回环 ⇒ 只有**本机**能发请求；远端必须先经隧道到本机 | `proxy.ts:5` 注释 + `assertLoopbackBind` |
| **已验证（2026-11-19，本机 WSL sshd 实测）** | `GatewayPorts yes` 时 `-R` 的绑定范围：我们写的是 `-R 127.0.0.1:0:…`，**服务端仍会把它放宽成 `0.0.0.0`** | 实测：`GatewayPorts no` → 监听 `127.0.0.1:18081`；改成 `yes` → 监听 **`0.0.0.0:18082` + `[::]:18082`** |

**由此新增的护栏**（`remote/tunnel-exposed`）：`launchSshDsh` 在 `-R` 建立后**回查远端实际监听地址**，只要有一条不是回环就关掉隧道并报错——
「看不见绑定结果」同样算不合格（空输出不当作验证通过）。这条是针对上表的**运行时**兜底：服务端策略不可控，就不能只靠我们写了 `127.0.0.1`。
纯函数判据（`isLoopbackOnlyBinding` / `buildForwardScopeScript`）有单测；**端到端也已验证**（`spikes/m4-multi-host/e2e-exposed.mjs`）：
- `GatewayPorts yes` → `LAUNCH_ERR code=remote/tunnel-exposed`，detail 里带着远端真实地址「`0.0.0.0:42571, [::]:42571`」，隧道被关掉；
- `GatewayPorts no`（阴性对照）→ `LAUNCH_OK remoteProxyPort=43789`，不误报。

## 3. iframe / 渲染面 —— 无此面

`iframe` / `webview` / `dangerouslySetInnerHTML` / `eval(` 在 `src` 内命中 **0**：ADR-0003 定的 C 型（复用官方 Remote 内核 + 自建 transport）不需要嵌远端页面，
因此没有「父窗口校验 / cookie 跨源」这一整类风险。

## 4. 远端权限与命令构造 —— 强

| 面 | 结论 | 证据 |
|---|---|---|
| 远端命令拼接 | 全部经 `shellQuote`（单引号 + `'\''` 转义）；注入用例实测挡住 `'; touch /tmp/x; '` | `posix-probe.ts`；P4 红队实测 `PWNED 未创建` |
| 本机 HTTP 面 | 只放行回环（`isLoopbackRequest`）+ 官方 `connection` 的 Host/Origin 围栏与 token；请求体上限 **64 KiB** 且超限 `destroy()` | `envelope.ts:18,67,97`；`index.ts:42` 注入 `connection` |
| 远端文件权限 | staging 目录 **0700**；实例登记写在同一个 0700 目录内 | `bootstrap.ts:299-302` |
| destructive 动作 | 远端残留清理必须 `confirm:true` + 未连接 + 进程内互斥锁 + 面板两步确认；**有活驻留实例时拒删 staging** | RFC-0006；`residue.ts planPurge`；红队三轮 |

## 5. 发现（均非高危）

| ID | 级别 | 描述 | 处置 |
|---|---|---|---|
| F1 | 低 | `/doctor` 与 `/anchors` 会把本机绝对路径回显给浏览器 | 回环 + 同源围栏内，且诊断本就需要路径；**知情接受**，写在此处 |
| F2 | 低 | 实例登记文件（含 token）未单独 `chmod 600`，依赖父目录 0700 | 目录已 0700；单文件权限留作 backlog（多用户同机场景才放大） |
| F3 | 低 | `maintenance purge` 是远端 `rm -rf` | 已按 D2/D3 收紧：confirm + 锁 + 未连接 + 活实例保护 + anchor 级作用域 + 逐条失败上报 |
| F4 | 信息 | 诊断/清理接口在跨站场景下不可读（响应不可读、无 CORS），但表单式 POST 仍可发出 | 与其它 POST 路由同一围栏；破坏性动作有 confirm 与锁，**不构成 CSRF** |

## 6. 未验证（如实列出）

1. `GatewayPorts yes` 下 `-R` 的实际绑定范围（需一台可控 sshd）；
2. ~~`hidepid=2` / 无 `/proc` 容器里实例判活~~ → **已验证并修复（2026-11-19）**：特权容器里 `mount -o remount,hidepid=2 /proc` 实测（`hidepid=invisible`），以 alice 身份看 bob 的 pid：`/proc/<pid>` 不可见、`kill -0` 被拒。**旧判活逻辑把这种 pid 判成已死**（脚本无输出 → 清理计划会删掉在用的登记）。已改成第三种结论 `UNKNOWN`，并让 `planPurge` 失败关闸（`skipReason: 'liveness-unknown'`，一个都不删）。修复后在同一个容器里复测：`UNKNOWN=26`。
3. 真实恶意远端（远端主动伪造 `session/list` 内容）对面板渲染的影响——只做了「解析失败即跳过」的代码级检查；
4. 本机多用户同机场景（F2 的前提）未实测。

## 7. 结论

- **无高危项**；A6「凭据不出本机」由「只绑回环 + 只认占位串 + 非占位串 403 + 不打印真值」四条独立护栏共同保证。
- 发布前若要再加一道：把 F2 的单文件权限补上（`chmod 600`），并把 §6-1 的 `GatewayPorts` 在一台可控 sshd 上实测。
