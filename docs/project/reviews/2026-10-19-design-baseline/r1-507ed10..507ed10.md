## 3. 失败预演与误用路径推演

**Steelman（先复述该产物最强的论证，并声明我接受其中哪些部分）**：这份设计最强的论证链是——(1) 形态选择由实测驱动而非偏好：A 型已有多个实现且暴露出结构性限制，B 型有参考实现可循，故先排除 A 型主形态（`docs/decisions/ADR-0001-host-on-remote.md:13-24`）；(2) 全部技术选择都放在「不改内核、只用文档化扩展点」的框内，并对四条已实测的宿主硬限制逐条给了对策（`docs/design/architecture.md:56-62`、`:136-137`）；(3) 把最贵的未知量（嵌入路线、工作区形态）前置到 1–2 周的 M0 spike，而非拖进 M1（`docs/design/milestones.md:5-17`）；(4) 验收表 A1–A10 与里程碑出口、质量门形成三层可测结构（`docs/design/requirements.md:34-45`、`docs/design/milestones.md:66-71`）；(5) 风险表主动登记 12+ 条风险而不是掩盖（`docs/design/architecture.md:127-138`）。**我接受 (1)(2)(3)(5) 的论证结构**；对 (4) 我接受其形式，但指出两处出口不可判定（R1-4、R1-5）——这不是措辞问题，而是「按哪份文档放行」无法机械回答。

## 5. 第一轮结论概要

- **对契约的判定建议：先修订，不得据此直接进入 M0**。设计骨架（形态决策、双后端抽象、状态机、失败分类、验收三层结构）足以支撑继续投入，但三处 P1 中任意一处都会在 M1–M2 变成返工：凭据反向通路缺机制（R1-1）、路线 C 判据不可证伪（R1-2）、工作区形态与已证伪事实冲突（R1-3）。
- **P1 阻断项 3 条**：R1-1、R1-2、R1-3。
- **修改方向（各一句话，最小修正，不作为独立指控）**：R1-1 在 Tunnel 组件与 ADR-0002 补上远端→本机的反向通路（`-R`／远端主动建连）并写明两条链路的差异化实现；R1-2 把 M0 的 C 判据换成「远端业务描述符能否进入本地构建产物 + 跨机 transport 由谁提供」的证伪式问题，并在 ADR-0003 写明判定阈值与全败回退；R1-3 删除方案 2 或把它替换为「锚点 + cwd 映射/投影」的接口定义，并把 M0 任务 4 改为验证映射层而非验证宿主限制。
- **P2（削弱项）7 条**：R1-4、R1-5、R1-6、R1-7、R1-8、R1-9、R1-10；**P3（低危）2 条**：R1-11、R1-12。合计 12 条指控，全部在契约范围内（无契约外指控）。
- **契约层缺陷：有**。已在 §1.3 登记 4 条，其中 C-1（Constraints 7 中「官方 Remote 内核为跨 realm MessageChannel」在证据底座与检出中均无可定位读取方）影响本轮对 Remote 内核类问题的定级口径，建议 R2 一并对契约做窄化或补锚点；C-2 建议补「判定标准」的可判定口径，否则 R1-5 只能按最小口径成立。
- **未取证项 6 项**（F3 工具名唯一性校验点、F6 MessageChannel 归属、F12 WSL 隧道必要性、F14 npm 名可用性、F15 官方桌面内置 remote、F17 时间基准可达性；F11 部分未取证）。这些项未用于定级，其中 F12 因证据底座内部冲突另行升级为 R1-7（依据为产物内部矛盾与 Constraints 6，而非「断言为假」）。
- **⚖️ 交人类裁决 2 项**：嵌入三路线的取舍本体（契约 Value Calls 1）、M0 工期预算（Value Calls 2）。R1 不对二者给结论。
- **对 R2 的建议复核点**：R1-2 与 R1-3 的 P1 定级依赖「契约 Constraints 4/7 是否覆盖『M0 待验证选项』这一形态」；若 R2 判定契约在该点上过窄，两条可降为 P2，但 R1-5（判定标准缺阈值）与 R1-1 不受影响，阻断结论不因此消失。
