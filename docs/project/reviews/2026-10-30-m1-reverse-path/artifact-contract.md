## Intent（要达成什么）

让决策者判定**「WSL 反向通路定档」这一条架构修订是否成立到可以据此实现**，具体回答三问：

1. **证据是否支撑结论**：由 `spikes/m1/wsl-closed-loop/` 的实测，能否推出「③ `wsl.exe --exec` stdio 桥为默认 /
   ① `mirrored` 直通为优化 / ② 宿主网关档退役」？三条档位的判词与实测证据是否同宽？
2. **实现者能否照着做而不掉坑**：把这条定档写进 `ADR-0002` 与 `architecture.md` 后，实现者是否还会遇到
   「必须去等一个已被移出尝试链的档位失败」这类死分支、或相反的「静默降级」漏洞？
3. **是否越权**：这次修订是否在不该动的地方动了刀——重开了已批准的决策（B 型形态 / 嵌入策略 / 工作区身份 /
   环境策略默认值），或把「未验证」写成了「已支持」？

产出裁决的形式：**P1 = 0（准予把定档当作已批准架构决策）** / **P1 > 0（阻断，须修订后重审）** /
**⚖️（争点落在无客观判据的价值取舍，交人类）**。

## Audience（给谁看 / 谁据此行动）

1. **实现者（本项目后续编码 agent）**：将按此定档实现 M1 的 `Backend` 反向通路——默认起 stdio 桥、探测到
   `mirrored` 直通则优先、不实现网关档；并据「硬失败」判定条件写失败路径。**本契约的核心受众是它。**
2. **项目所有者（本机用户）**：需要知道这条定档是「有实测支撑的决策」还是「Lead 的一厢情愿」，再决定是否
   让它沉淀进 `ADR-0002` 的正式决策体。

## Constraints（不可协商项）

1. **形态 = B 型（宿主远端）**；凭据不出本机且**双向**（远端必须有物理可达通路打到本机代理）。
   *来源：上一单元契约 Constraints 1/3，ADR-0001 已接受；本轮不得重开。*
2. **绝不把本地代理端口绑到 `0.0.0.0`**（`architecture.md` §7.0 安全约束）。**本轮定档的直接动因**：档位 ②
   要成立必须绑宿主网卡，与这条互斥。
3. **失败要响**：禁止静默降级。本轮的**具体判据**——「硬失败」的触发条件必须是一个**可达**的条件；若文档
   要求「等已被退役的档位也失败才硬失败」，该条件永不为真 ⇒ 等价于静默降级 ⇒ 契约违背。
4. **未实测必须标「未验证」，且结论强度与证据同宽**（AGENTS.md §2.6；上一单元 Evidence Bar 第 5 条）。
   本轮的**具体判据**：只在本机 `mirrored` 下测过的东西，不得表述为「在所有网络模式/所有后端上成立」。
5. **不修改 DSH 内核，只用已文档化扩展点**；不引入新的第三方运行时依赖（`spikes/` 脚本零第三方依赖，
   只用 Node 内置模块）。
6. **增量修订，不重开已定决策**：本轮允许改的只有「WSL 反向通路的档位定位」与「硬失败判定条件的随之收窄」。
   B 型形态 / 嵌入三路线 / 工作区身份方案 / 环境策略默认 `reuse` 均为**已裁决项**，改动即为越界。
7. **判据必须可机械复跑**：定档的每条断言都要能由一个命令复现（`node spikes/m1/wsl-closed-loop/probe.cjs`），
   且该命令存在一个**显式变异入口**并已被实测证明会 FAIL（否则「全绿」不构成证据）。
8. **历史证据保留**：`spikes/m0/**` 的原文不删除、不改写，只允许追加补注并指向新定档。

## Out of Scope（明确不评）

1. **`probe.cjs` / `relay.cjs` 自身的实现质量与健壮性**（异常分支、资源上限、跨平台细节）：只核验其**产出的
   结论**是否被如实引用（按 Constraints 4 / 7）。脚本可读、可复跑即可，不评代码风格。
2. **上一交付单元已闭合的 13 条指控**（`R1-13`~`R1-25`，`delta-r2` 已裁决：11 条驳回、2 条降 P2）：
   已裁决事项不得重开；本轮若发现它们的**修复被本次改动破坏**，按「本次引入的次生破坏」单列，不算重开。
3. **措辞、排版、术语风格偏好**；文档篇幅；Markdown 写法。
4. **M1 的产品行为**（瞬移面板 UI、插件注册、凭据替换实现、断线重连）：一行代码都没开始，不在本次范围。
5. **性能优化**：只要求「数量级合理且已量化」，不要求把 ≈19 ms/请求 或 40 MiB/s 调到某个目标值。
6. **`.agents/skills/**`、`.review-context/**`、`.goal-loop/**`**：工具与运行时状态不在审查范围。
7. **真实 NAT 环境下的实测**：改 `.wslconfig` 会影响宿主上所有 distro，本轮**没有**做；只要求文档如实标注。

## Evidence Bar（什么算证据）

1. **产物内确切位置** `文件:行`（或章节号 + 引文片段）。只给「通篇感觉」「大意是」的指控不予受理。
2. **可复现命令 + 原始输出片段**：例如 `node spikes/m1/wsl-closed-loop/probe.cjs` 的 PASS/FAIL 行；涉及 DSH 宿主
   事实时须给本机检出的 `绝对路径:行`（`D:/workspace/tools/deepseek-harness/`）。
3. **外部权威来源需 URL**（WSL 官方文档 / DSH 官方仓库 / 上游 issue），用于核验「`mirrored` 需要 Win11 22H2+」
   这类平台事实。
4. **产物内部矛盾**：同一事实在两份文档中互斥，**双方各自**给 `文件:行`；只举一侧不算。
5. **实测证据三条件**（缺一即按「未验证写成已支持」指控）：① 有可复现命令与原始输出；② 有「未验证」边界标注；
   ③ 结论强度与证据同宽。

不接受「业界通常如此」「按经验」这类无锚点论据；不接受把「在本机 `mirrored` 下通了」推论成「普遍可用」。

## Value Calls（预期的价值取舍点，无客观判据，可判 ⚖️ 不可判定）

1. **≈19 ms/请求 的固定开销对交互体验是否可接受**：属取舍 → ⚖️。
   **但**「是否给出了量化依据（而不是只说『略慢』）」**可判**。
2. **① `mirrored` 直通的探测要不要做**（探测有成本，收益只在 `mirrored` 机器上）：选不选是取舍 → ⚖️。
   **但**「探测的收益/成本与失败时的行为是否写明」**可判**。
3. **② 网关档「退役」而非「保留为注释/文档记录」**：保留方式属取舍 → ⚖️。
   **但**「退役后是否留下可追溯理由与重启条件」**可判**（若理由缺失，实现者无法判断能否复活它）。
4. **把定档写进 `ADR-0002` 修订记录而不是新开一份 ADR**：属文档组织取舍 → ⚖️。
   **但**「与该 ADR 既有两条修订记录的骨架是否一致、是否声明了连带影响」**可判**。
