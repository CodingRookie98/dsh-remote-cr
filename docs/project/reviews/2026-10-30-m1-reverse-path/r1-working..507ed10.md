## Constraints（不可协商项）

1. **形态 = B 型（宿主远端）**；凭据不出本机且**双向**（远端必须有物理可达通路打到本机代理）。
   *来源：上一单元契约 Constraints 1/3，ADR-0001 已接受；本轮不得重开。*
2. **绝不把本地代理端口绑到 `0.0.0.0`**（`architecture.md` §7.0 安全约束）。**本轮定档的直接动因**：档位 ②
   要成立必须绑宿主网卡，与这条互斥。
3. **失败要响**：禁止静默降级。本轮的**具体判据**——「硬失败」的触发条件必须是一个**可达**的条件；若文档
   要求「等已被退役的档位也失败才硬失败」，该条件永不为真 ⇒ 等价于静默降级 ⇒ 契约违背。
4. **未实测必须标「未验证」，且结论强度与证据同宽**（AGENTS.md §2.6；上一单元 Evidence Bar 第 5 条）。
   本轮的**具体判据**：只在本机 `mirrored` 下测过的东西，不得表述为「在所有网络模式/所有后端上成立」。
5. **不修改 DSH 内核，只用已文档化扩展点**；不引入新的第三方运行时依赖（`spikes/` 脚本零第三方依赖，
   只用 Node 内置模块）。
6. **增量修订，不重开已定决策**：本轮允许改的只有「WSL 反向通路的档位定位」与「硬失败判定条件的随之收窄」。
   B 型形态 / 嵌入三路线 / 工作区身份方案 / 环境策略默认 `reuse` 均为**已裁决项**，改动即为越界。
7. **判据必须可机械复跑**：定档的每条断言都要能由一个命令复现（`node spikes/m1/wsl-closed-loop/probe.cjs`），
   且该命令存在一个**显式变异入口**并已被实测证明会 FAIL（否则「全绿」不构成证据）。
8. **历史证据保留**：`spikes/m0/**` 的原文不删除、不改写，只允许追加补注并指向新定档。

## Out of Scope（明确不评）

1. **`probe.cjs` / `relay.cjs` 自身的实现质量与健壮性**（异常分支、资源上限、跨平台细节）：只核验其**产出的

2. **上一交付单元已闭合的 13 条指控**（`R1-13`~`R1-25`，`delta-r2` 已裁决：11 条驳回、2 条降 P2）：
   已裁决事项不得重开；本轮若发现它们的**修复被本次改动破坏**，按「本次引入的次生破坏」单列，不算重开。
3. **措辞、排版、术语风格偏好**；文档篇幅；Markdown 写法。
4. **M1 的产品行为**（瞬移面板 UI、插件注册、凭据替换实现、断线重连）：一行代码都没开始，不在本次范围。
5. **性能优化**：只要求「数量级合理且已量化」，不要求把 ≈19 ms/请求 或 40 MiB/s 调到某个目标值。
6. **`.agents/skills/**`、`.review-context/**`、`.goal-loop/**`**：工具与运行时状态不在审查范围。

## Evidence Bar（什么算证据）

1. **产物内确切位置** `文件:行`（或章节号 + 引文片段）。只给「通篇感觉」「大意是」的指控不予受理。
2. **可复现命令 + 原始输出片段**：例如 `node spikes/m1/wsl-closed-loop/probe.cjs` 的 PASS/FAIL 行；涉及 DSH 宿主
   事实时须给本机检出的 `绝对路径:行`（`D:/workspace/tools/deepseek-harness/`）。
3. **外部权威来源需 URL**（WSL 官方文档 / DSH 官方仓库 / 上游 issue），用于核验「`mirrored` 需要 Win11 22H2+」
   这类平台事实。
4. **产物内部矛盾**：同一事实在两份文档中互斥，**双方各自**给 `文件:行`；只举一侧不算。
5. **实测证据三条件**（缺一即按「未验证写成已支持」指控）：① 有可复现命令与原始输出；② 有「未验证」边界标注；
   ③ 结论强度与证据同宽。

不接受「业界通常如此」「按经验」这类无锚点论据；不接受把「在本机 `mirrored` 下通了」推论成「普遍可用」。

## Value Calls（预期的价值取舍点，无客观判据，可判 ⚖️ 不可判定）

1. **≈19 ms/请求 的固定开销对交互体验是否可接受**：属取舍 → ⚖️。
   **但**「是否给出了量化依据（而不是只说『略慢』）」**可判**。

3. **② 网关档「退役」而非「保留为注释/文档记录」**：保留方式属取舍 → ⚖️。

- **契约可判定性评估**: 六项齐备（Intent 三问、Audience 两类、Constraints 1–8、Out of Scope 1–7、Evidence Bar 1–5、Value Calls 1–4 且各自标注了可判/不可判的切分），总体可判定。但有四处会影响本轮裁定，必须单列：
  1. **Constraint 3 的具体判据建立在一个不成立的前提上**。契约写「若文档要求『等已被退役的档位也失败才硬失败』，该条件永不为真」。事实相反：② 在本设计下**恒失败**（`probe.cjs:156-168` 只绑 `127.0.0.1`，网关 IP 上必然无监听者，判定走 SKIP），因此旧口径「三档全失败」在布尔上恒等价于「① 不通 且 ③ 不通」，与新口径**完全等价且同样可达**。我实测过这条可达性：删掉中继（`spikes/m1/wsl-closed-loop/README.md:165`）时 A6 立即 FAIL，硬失败条件被真实触发。所以本轮的「收窄」是省掉一次必然失败的探测分支，不是修补一个不可达条件——契约把审查者引向一条实际不存在的罪（详见 F16）。
  2. **契约把 `ADR-0003` 与 `ADR-0005:79` 描述为「上一轮登记的勘误」，与产物实际改动规模不符**。产物实测：`ADR-0003` 为 +120/−19 的整篇重写（标题、状态、结论先行、判据与取证、T1–T6 阈值表全部重写），`ADR-0005:79` 删除了一条既有回退分支。审查者无法据此判定「勘误豁免」的边界在哪里（见 R1-8）。
  3. **Out of Scope 1（不评 probe/relay 实现质量）与 Constraint 7（变异入口必须实测 FAIL）在「断言可假性」上重叠**，契约未说明可假性归属哪一侧。本报告的处理口径：不评代码风格与异常分支，只评「`断言可假` 这一主张本身是否成立、以及文档对变异结果的陈述是否与实跑一致（R1-4 / R1-5 均按此口径构造，请 R2 依此裁定是否落在范围内）。

## 3. 失败预演与误用路径推演

- **Steelman（必填、必在最前）**: 该产物最强的论证是——**「默认通路必须与网络拓扑解耦」这一条先验，被 ③ 的结构性质独立支撑，与 ② 的存废无关**：`wsl.exe --exec` 走的是进程管道（`relay.cjs:57` 在 distro 内 `listen(0,'127.0.0.1')`，端口只回报给宿主父进程），不占用任何宿主网卡、不依赖 `mirrored`、不需要 `GatewayPorts`，因此无论 ① 通不通、② 存不存在，M1 都有一条可用的反向通路；而 ① 只在 `mirrored` 下可用这一条已被 M0（仅命中一次）与 M1（P50 1.5–1.6 ms，20/20）双向确认，把它降为「优化项」在工程上是正确的优先级排序；两级 dispose 有 A10 的进程计数佐证（35→38→35）；`spikes/m1/wsl-closed-loop/README.md:163-167` 也确实留下了变异入口并实测出 exit=1，不是恒绿探针。我接受其中 **A**：③ 作默认可行且不依赖 `mirrored` 的判断成立（F2/F3/F14 均可复现）；**B**：① 只能当优化项的判断成立（① 依赖 `mirrored`，而 `mirrored` 需 Win11 22H2+，F9 已由外部权威核实）；**C**：硬失败判定收窄到「③ 起不来且 ① 不通」在可达性上没有问题（F16 已实测，收窄前后均可达），并且收窄消除了「实现者为 ② 写一个注定失败的探测」这一真实浪费。此外，`spikes/m0/evidence/r1-1-reverse-tunnel.md:67` 采用「保留原文 + 追加补注」而不是改写历史，是 Constraint 8 的正确做法。

- **失败归因（过去时）**:
  1. **它已经失败了：② 的退役理由被写成一条不存在的实验，于是「退役」在证据链上悬空**。`ADR-0002:103` 与 `:116` 把「把假代理改绑 `0.0.0.0` 后网关 IP 仍 `curl: (7)`」写成 A5 的实测结论，而 A5 的实现（`probe.cjs:156-168`）只做「在网关地址上找监听者」，脚本里连一个绑 `0.0.0.0` 的分支都没有，`:94` 反而明令「绝不 0.0.0.0」。半年后任何人想重建这条决策，唯一的取证入口是 `probe.cjs`，而它会给出「不存在这项检查」的结论——定档第三条判词（② 退役）被归因为「用一个不存在的实验关掉了一个档位」。
  2. **它已经失败了：定档只落到一半，网关仍留在主流程的枚举里，于是「死分支」正是这条修订要防的东西，却被同批改动重新造出来**。`architecture.md:53` 第 9 步把反向通路写成「（-R / 网关 / stdio 桥）」，`:347` §14 的后端矩阵正向通道列仍写「三档探测：distro loopback → 宿主网关 → stdio 桥」，`ADR-0002:83` 与 `:95` 仍以「全失败硬失败」「三档降级」收尾——而同一批的 `ADR-0002:127` 已把 ② 移出尝试链。实现者照 §14 写 Backend 就会写出网关分支，照 `:127` 写就会跳过它，两种实现都能在文档里找到依据。
  3. **它已经失败了：代价形态被当作定值刻进两份设计文档，而同一个命令第二次跑出的倍数是它的三倍**。`architecture.md:177` 的 `固定开销 6.26×`、`ADR-0002:117` 的 `≈19 ms / ≈40 MiB/s`、`spikes/m1/README.md:19` 的 `≈10–19 ms（直通的 6 倍）` 全部来自 `spikes/m1/wsl-closed-loop/README.md:115-120` 那一次运行；我在同一台机器重跑得 `a 19.27×`。当有人据此做预算，会用最小的那个倍数，得出「桥的固定开销可忽略」的偏乐观结论。
  4. **它已经失败了：探针在故障态给出的信号是 SKIP 与 PASS，而不是 FAIL，于是「全绿」这件事在部分场景下失去了门禁含义**。A4（① 直通，是「优化项」判词的唯一证据）没有任何 bad 分支（`probe.cjs:151-154`），负控下它安静地变成 SKIP；A11 在桥完全不通、载荷 `0/0 B` 时反而打印 `PASS … 可承载模型请求`（F15）。一个只看 exit code 的流水线会把这两条当成通过。
  5. **它已经失败了：M2 的 SSH 后端会照抄这套定档的骨架，把一条 WSL 特有的理由复制到不适用的场景**。`ADR-0002:111` 的理由是「要让 ② 成立必须绑宿主网卡，而那违反绝不绑 0.0.0.0」——这条因果链只在「本机代理 ↔ 远端同主机」的拓扑下成立；SSH 侧的 `-R` 绑的是**远端** `127.0.0.1`（`architecture.md:183` 明确 GatewayPorts no），与「本地代理绑 `0.0.0.0`」不是同构命题。半年后若有人按「退役理由 = 与安全约束互斥」的模板去审 SSH 的降级链，会把本来合法的 `-R` 也判成「与安全约束互斥」。

- **误用路径**: 一个赶时间、只读标题与修订表的读者，会从 `ADR-0002:99` 标题「③ stdio 桥为默认，② 网关档退役」+ `:109-111` 表格得到「② 因安全原因退役，不必实现」，然后跳过整段证据。这在 `mirrored` 机器上无害，但在**一台 NAT 机器上、且该 distro 未装 node（③ 起不来）**时，用户面对的是硬失败，而文档从未承认「在这台机器上 ② 本来是唯一可能的非 ③ 出路」——因为「② 的成立条件」这一格本身就没有被验证过（F8）。第二个误读者只读 `spikes/m1/README.md:19` 的「≈10–19 ms/请求（直通的 6 倍）」，会把 10–19 当作抖动区间写进预算，而实际抖动来自 ① 侧 `a` 从 3.1 ms 掉到 1.1 ms（F5），抖动的是**比值**而不是绝对值。

## 5. 第一轮结论概要

- **可定级指控 9 条：P1 × 3（R1-1、R1-2、R1-3）、P2 × 6（R1-4 至 R1-9）**。按契约给定的裁决形式，**P1 > 0 ⇒ 阻断，须修订后重审**，不宜把当前定档当作已批准架构决策。
- **Top-3 焦点**：① **R1-2**——② 退役的理由链（「必须绑宿主网卡」）既未被产物证据支撑，也被我本机实测反证（绑 `0.0.0.0` 后宿主全部 IPv4 从 distro 不可达），且未留下重启条件；这直接否定 Intent 第 1 问的第三条判词。② **R1-1**——`ADR-0002:103/:116` 声称的「改绑 0.0.0.0 后仍 `curl: (7)`」在其唯一声明的复跑命令里根本没有对应实验，Constraint 7 的「可机械复跑」在 ② 这条判词上失效。③ **R1-3**——网关仍留在 `architecture.md:53`（主数据流第 9 步）与 `:347`（§14 后端矩阵）以及 `ADR-0002:83/:95`、`milestones.md:49`，构成与新口径互斥的双份规范，正好复现 Intent 第 2 问要防的死分支；这些行在 diff 中全为新增，不能归因于历史遗留。
- **契约本身是否需要修订：需要两处**。其一，Constraint 3 的具体判据把「等已退役档位失败才硬失败 ⇒ 条件永不为真」当成契约违背的样板，但 ② 在本设计下**恒失败**，「三档全失败」与新口径在布尔上等价且同样可达（F16 已实测硬失败可被触发），该判据实际上无法成立，会诱导审查者去找一条不存在的罪。其二，契约把 `ADR-0003` 与 `ADR-0005:79` 描述为「上一轮登记的勘误」，与 +120/−19 的整篇重写和「删除既有回退分支」的实际改动不符；建议在下一轮契约里把「勘误豁免」的边界写成「不改变状态、不删除既有分支」。
- **增量再循环核验**：本节未激活（非 DELTA_RE_LOOP 模式）。但按 §5 要求附带一句「改了 A 漏了 B」的痕迹判定：**存在**。同一批改动已把 `ADR-0002:127` 与 `architecture.md:48` 收窄到「③ + ①」，却漏改 `architecture.md:53`、`:347`、`:328`、`ADR-0002:83`、`:95`、`milestones.md:49`（R1-3）；另有一处「同一批被改过两次」的痕迹：`spikes/m1/README.md:19` 的「≈10–19 ms」把两次运行的不同 `a` 值写成一个区间，而 `ADR-0002:117` 只取了上界「≈19 ms」——同一事实在同一批内以两种精度出现，且都未标样本数。
